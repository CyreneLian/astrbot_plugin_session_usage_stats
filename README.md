# 📊 astrbot_plugin_session_usage_stats
# 🌸 模型用量统计与告警插件

一款面向 AstrBot 的高性能模型用量统计与可视化仪表盘插件。支持统计全部模型在过去 24小时 / 7天 / 30天 / 1年 / 全部历史内的调用次数、Token 消耗（输入/输出/总额）与对话轮数；提供美观直观的 Web 仪表盘，涵盖趋势概览、模型与平台占比、Top 会话排行与明细表格；内置 30 天小时桶精细化自动瘦身与默认 1 年全量保留的双层清理机制，兼顾毫秒级极速查询与长久历史追踪；并支持每日用量告警，Token 超限自动推送到指定 QQ。

## ✨ 功能特性

- 支持网页仪表盘（涵盖总览卡片、Top 会话排行、平台占比圆环图、模型占比圆环图、趋势概览折线图与明细表格搜索排序）
- 统计模型用量数据（涵盖过去 24 小时、过去 7 天、过去 30 天、过去 1 年与全部历史）
- 保留会话维度辅助统计，方便定位模型消耗来源
- 统计字段包括模型调用次数、输入 Token、输出 Token、总 Token、完成回复轮数与用户/Bot 消息数
- 支持模型调用统计（涵盖对话模型与全部模型维度，支持 Token 与次数切换）
- 支持每日用量告警（全局 / 单会话双阈值，填 0 不启用；超限自动向 QQ 私聊或群聊推送合并消息，支持多目标、冷却记录持久化与跨天自动重置）
- 支持 QQ / aiocqhttp 等不稳定写入历史库的平台通过事件捕获统计
- 支持清空统计数据，并通过 `clear_at` 避免旧历史数据重新回流（手动清空会重组数据库文件瘦身；自动清理只删除旧数据、不执行 VACUUM，内部带 1 小时冷却防抖，稳定保持每小时最多执行一次）

### 📌 其它平台使用建议

如果需要在未测试的平台上使用本插件，建议：

1. **先在测试场景验证核心数据**：消息轮数、Token 消耗、Top 会话等是否正常落库
2. **自动扫描已强制开启**：自动扫描与事件钩子捕获均已强制启用，无需额外配置
3. **留意主历史库写入情况**：插件依赖 `platform_message_history` 表的历史数据，未测试平台可能写入不完整
4. **使用「会话统计诊断」命令**：`会话统计诊断` 可以查看 Provider wrapper 接管情况
5. **若该平台依赖主历史库外的数据源**：可能需要自行扩展统计逻辑

### ⚠️ QQ / aiocqhttp 说明

QQ 平台的消息历史写入不够稳定，本插件已强制开启事件钩子捕获作为兜底，无需额外配置。

## ⚙️ 配置说明

在 AstrBot 管理面板的插件配置页面中，配置项分为两个分组：

### 📦 用量统计设置

| 配置项 | 类型 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- |
| `auto_scan_interval_minutes` | int | `5` | **自动扫描间隔（分钟）**（设定增量扫描任务的执行间隔，越快 24小时视图越新，但扫描越频繁） |
| `scan_batch_size` | int | `500` | **单次扫描最大消息数**（防止单次扫描处理过多消息，影响 AstrBot 响应速度） |
| `enabled_platforms` | list | `["webchat"]` | **历史消息扫描的平台列表**（启用历史消息扫描的平台，适用于 webchat 等写历史表的平台） |
| `include_threads` | bool | `false` | **是否统计网页端线程对话**（开启后，网页端创建的「子线程对话」也会纳入用量统计；关闭则仅统计普通网页对话） |
| `event_capture_platforms` | list | `["aiocqhttp"]` | **事件钩子捕获的平台列表**（启用事件钩子捕获的平台，默认 aiocqhttp（QQ）） |
| `auto_cleanup_enabled` | bool | `true` | **是否开启自动清理旧统计数据**（开启后每隔 1 小时会删除超过保留天数的全量桶数据（日/周/月）。注意：为了精简数据库大小，超过 30 天的小时桶（hour）数据为系统固定自动清理，不受此开关影响） |
| `auto_cleanup_retention_days` | int | `365` | **全量统计数据保留天数**（仅影响插件自身数据库中的全量数据（日/周/月总账桶），开启自动清理后超过此天数的数据将被彻底清除） |

### 🔔 用量告警设置

| 配置项 | 类型 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- |
| `alert_enabled` | bool | `false` | **是否启用用量告警**（开启后，每日 Token 用量超过阈值时会向指定 QQ 发送告警消息） |
| `alert_daily_token_threshold` | int | `0` | **全局每日 Token 告警阈值**（填 0 不启用。当日所有会话累计 Token 超过此值时触发全局告警） |
| `alert_session_token_threshold` | int | `0` | **单会话每日 Token 告警阈值**（填 0 不启用。单个会话当日 Token 超过此值时触发单会话告警） |
| `alert_target_id` | list | `[]` | **告警接收目标**（支持多个目标，私聊接收的 QQ 号直接填，群聊接收的群号需加 `g:` 前缀（如 `g:12345678`）） |
| `alert_check_interval_minutes` | int | `30` | **告警检查间隔（分钟）**（每隔多少分钟检查一次用量是否超限；插件启动 / 重载后约 30 秒执行首次检查） |

## 💬 聊天指令

| 指令 | 说明 |
| --- | --- |
| `会话统计 今日` | 查看当前会话过去 24 小时的用量统计 |
| `会话统计 本周` | 查看当前会话过去 7 天的用量统计 |
| `会话统计 本月` | 查看当前会话过去 30 天的用量统计 |
| `会话统计 模式` | 查看当前自动扫描、扫描间隔、单次上限、平台与事件捕获状态 |
| `会话统计 补扫` / `重扫` | 手动触发增量扫描，返回处理消息数、会话数与最新游标 |
| `会话统计诊断` | 查看 Provider 包装、模型调用记录与告警运行状态（任务存活 / 上次检查 / 冷却记录），排查统计异常 |
| `会话统计全部 今日` / `本周` / `本月` | 查看全站过去 24 小时 / 7 天 / 30 天的汇总统计 |

> **提示**：所有指令默认仅管理员可用，可在 AstrBot 指令管理中调节。

> **提示**：这里的“今日 / 本周 / 本月”均指滚动时间窗口（过去 24小时 / 7天 / 30天），非自然日 / 周 / 月。

## 📊 网页仪表盘

可在 AstrBot 插件页面直接打开“模型用量统计”网页（`pages/stats/index.html`）。

- **⏳ 时间范围切换**：支持 24小时 / 7天 / 30天 / 1年 / 全部历史
- **📋 总览卡片**：汇总显示会话数、总轮数、总/输入/输出 Token
- **🏆 Top 会话**：展示用量前 10 会话（支持按 Token / 轮数排序）
- **🥧 平台占比**：圆环图展示平台分布（支持按 Token / 轮数切换）
- **🍩 模型占比**：展示模型调用（支持对话模型/全部模型，按 Token/次数切换，支持零值隐藏与“其它”展开）
- **📈 趋势概览**：折线图展示趋势变化（按小时/天/月聚合）
- **📑 明细表格**：会话明细列表，支持搜索 ID 与多列双向排序

## ❓ 常见问题

**Q: 为什么从「对话模型」切换到「全部模型」时，有的模型只在对话中使用，但数据却增长了？**

A: 因为一次对话中，同一个对话模型可能会被多次调用——比如执行工具调用（Function Calling）。这些中间步骤的模型调用被 Provider wrapper 捕获到 model_call_stats 的其它模型部分（system/background），算进「全部模型」但不进「对话模型」。「对话模型」只统计对话流程最终完成的那一次回复。所以切换视角后，同一个模型的数据增长，正是工具调用中间步骤的消耗被统计进来了，属于正常口径差异。

**Q: 为什么设置了告警却收不到？**

A: 请依次检查：① 检查 astrbot 平台配置中配置了 QQ 平台；② 「是否启用用量告警」已开启，且对应阈值大于 0（两个阈值填 0 均表示不启用该类告警）；③ 「告警接收目标」已填写 QQ 号（私聊）或带 `g:` 前缀的群号（群聊）；④ 发送 `会话统计诊断` 查看「📊 告警状态」中的任务存活与上次检查时间——插件启动 / 重载后约 30 秒才会执行首次检查。

**Q: 插件重载或重启后，告警会重复发送吗？**

A: 不会。同类告警（全局 / 单会话）同一天仅发送一次，冷却记录持久化保存在数据库中，重载或重启后自动恢复，不会重复发送；跨天后自动重置，新的一天重新计算。若某次发送全部失败，则不会记录冷却，下次检查时会携带最新数据重新合并发送。
